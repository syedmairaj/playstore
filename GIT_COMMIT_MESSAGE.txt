feat: complete competitor keyword staging system with end-to-end data flow

## Problem
Competitor keyword staging was never inserting data into the database despite
complete infrastructure. Root causes:
1. Missing keywordSurfaces prop in CompetitorSpySnapshotCard component
2. Unique constraint violations on duplicate analyses (error 23505)
3. Retrieval query using unsupported PostgreSQL ->> operator in Supabase filter

## Solution

### 1. Component Fix (CompetitorSpyClient.tsx)
- Wrapped snapshot card in IIFE to extract keyword array before rendering
- Now passes keywordSurfaces prop correctly, enabling useEffect trigger

### 2. Duplicate Handling (staging-vault-service.ts)
- Graceful duplicate detection: catches 23505 errors and treats as success
- Rationale: analyzing same competitor twice should not error
- Added post-insert verification query to confirm data in database
- Comprehensive 20+ checkpoint logging for debugging

### 3. Retrieval Query Fix (keywords/route.ts)
- CRITICAL: Supabase JS client does NOT support PostgreSQL ->> in filters
- Solution: fetch all records for workspace/signal_type/language, filter client-side
- Now correctly matches metadata.competitor_id against query parameter

### 4. Enhanced Logging
- Insertion: debug tracers at entry, metadata checks, schema validation, about-to-insert, success
- Retrieval: pre-query vault inspection, detailed query debug, signal found confirmation
- Verification: immediate post-insert read-back to confirm data persistence
