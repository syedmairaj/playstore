KEY ARCHITECTURE RULES (Now Enforced)
════════════════════════════════════════════════════════════════════════════════

RULE 1: Metadata is NEVER stringified
  ✓ Passed as: { competitor_id: '...', keywords_by_strategy: {...} }
  ✗ NOT as: '{"competitor_id":"...","keywords_by_strategy":{...}}'

RULE 2: Content is ALWAYS stringified
  ✓ Passed as: JSON.stringify({ keywords: [...] })
  ✗ NOT as: { keywords: [...] }

RULE 3: signal_type MUST match exactly
  ✓ INSERT: signal_type: 'competitor_weakness'
  ✓ SELECT: .eq('signal_type', 'competitor_weakness')
  ✗ NEVER: signal_type = 'exploit_data' or 'COMPETITOR_WEAKNESS'

RULE 4: Language MUST be 'en' or 'ar' ONLY
  ✓ Accepted: 'en', 'ar'
  ✗ NOT: 'EN', 'arabic', 'english', null, undefined

RULE 5: metadata.competitor_id is REQUIRED
  ✓ MUST be present: { competitor_id: 'com.fittrack.pro' }
  ✗ CANNOT be: null, undefined, empty string, or omitted

HOW TO TEST

TEST 1: English Keywords (EN)
  1. Rebuild: npm run build
  2. Start server: npm run dev
  3. Go to Competitor Spy module

  5. Analyze a competitor
  6. Check server console for: ✓ Metadata validation passed

  8. Verify keywords display in UI

TEST 2: Arabic Keywords (AR)
  1. Switch language to Arabic
  2. Analyze the SAME competitor again
  3. Check server console for: ✓ Metadata validation passed (language: ar)
  4. Check server console for: ✓ SIGNAL FOUND
  5. Verify DIFFERENT keywords appear (Arabic, not English)
  6. Verify NO mixing of languages

TEST 3: Database Verification
  1. Open Supabase console
  2. Go to SQL Editor
  3. Run:
     SELECT
       metadata->>'competitor_id' as competitor_id,
       language,
       jsonb_array_length(metadata->'keywords_by_strategy'->'high_volume') as count
     FROM workspace_staging_vault
     WHERE signal_type = 'competitor_weakness'
     LIMIT 5;
  4. Expected: All fields populated (no NULL), counts > 0
